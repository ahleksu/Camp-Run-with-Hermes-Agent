Layer 1 · MCP server

One tool, one business question.

No tool takes raw SQL. Only two tools write, and each write is logged to ops_actions.

  • Read
  • branch_scorecardEvery branch on seven measures
  • list_open_ticketsUrgent first, then oldest
  • list_unreplied_bad_reviewsWith the review text
  • list_stockout_risks2 days of cover, no order coming
  • list_expiring_stockWithin 3 days, cost at risk
  • list_supplier_slipsPromise versus real lead time
  • Write, after a yes
  • escalate_ticketRaise to urgent, log the reason
  • draft_review_replySave a draft, never publish
Layer 105
Also mention: list_recent_actions stops repeat escalations, and 11 tests run on a temporary copy of the database. About 25 seconds.
Layer 2 · Skill

The same briefing every morning.

It triggers on plain requests like "what needs attention". Pane buttons send narrow requests that skip straight to one action.

  1. Score every branch with the scorecard
  2. Pick three by combined rank, like the pane
  3. Drill down only where a branch was picked
  4. Check history so nothing is done twice
  5. Propose at most three actions and ask
  6. Act only after an explicit yes
Layer 206
The skill also lists pitfalls: old tickets are an aging backlog, numbers are windowed, never claim a reply was published. About 25 seconds.

What the agent can touch, and what it cannot.

Two writes only.

Escalate a ticket or save a reply draft. No delete, no publish, no edits to other tables.

Every write is logged.

Each one adds a row to ops_actions with the reason, and the pane shows it.

A person says yes first.

The skill asks "Go ahead?" with the exact text. Running a write twice changes nothing.
